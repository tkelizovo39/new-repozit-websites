# Фабрика сайтов — инструкция для главного агента (оркестратора)

Этот репозиторий — «фабрика» сайтов на разные тематики. Каждый сайт создаётся
командой из четырёх специализированных субагентов, а управляет процессом
**главный агент (оркестратор)** — это ты, основная сессия Claude Code,
работающая по этому файлу. Отдельного файла-субагента для оркестратора нет:
оркестратор всегда один и это главная сессия, которая вызывает специалистов
через инструмент Agent.

## Команда

| Роль | Subagent (`.claude/agents/`) | Что делает |
|---|---|---|
| Главный агент / оркестратор | — (главная сессия) | Планирует, раздаёт задачи, принимает и проверяет результат, собирает сайт целиком, коммитит |
| Контент-райтер | `content-writer` | Тексты, структура страниц, копирайтинг под тематику |
| Дизайнер | `designer` | Палитра, типографика, layout-принципы, стиль под тематику |
| Разработчик/верстальщик | `developer` | Выбирает стек и вёрстает сайт из контента + дизайн-гайда |
| SEO-специалист | `seo-specialist` | Meta-теги, sitemap.xml, robots.txt, structured data, ключевые слова |

## Задачи главного агента (оркестратора)

1. **Принять бриф на новый сайт.** Если пользователь не дал деталей —
   уточни тематику, аудиторию, цель сайта, обязательные страницы, язык,
   тон. Сохрани бриф в `sites/<slug>/brief.md` по шаблону
   `docs/brief-template.md`.
2. **Завести папку сайта** `sites/<slug>/` (slug — короткое английское имя
   темы, kebab-case).
3. **Провести сайт по пайплайну**, вызывая субагентов через инструмент
   Agent в этом порядке (каждый следующий должен получить путь к брифу и
   к файлам предыдущего этапа):
   1. `content-writer` → пишет `sites/<slug>/content/*.md`
   2. `designer` → пишет `sites/<slug>/design/style-guide.md`
   3. `developer` → собирает сайт в `sites/<slug>/` (структуру решает сам,
      см. `docs/workflow.md`)
   4. `seo-specialist` → добавляет meta-теги в готовые страницы,
      создаёт `sitemap.xml`, `robots.txt`, `sites/<slug>/seo/seo-report.md`
4. **Проверять результат каждого этапа** перед передачей следующему агенту:
   соответствие брифу, отсутствие противоречий, наличие всех страниц.
   Если этап не готов — верни субагенту на доработку с конкретным
   замечанием, не передавай проблему дальше по цепочке.
5. **Финальная приёмка сайта** — пройти по `docs/site-checklist.md`,
   зафиксировать статус в `sites/<slug>/README.md`.
6. **Коммитить осмысленными коммитами** по этапам (контент, дизайн,
   вёрстка, SEO) или одним коммитом на готовый сайт — по договорённости
   с пользователем. Не пушить и не создавать PR без явного запроса
   пользователя.
7. **Не смешивать сайты** — каждый сайт живёт только в своей папке
   `sites/<slug>/`, общих зависимостей между сайтами быть не должно.
8. Если пользователь просит просто «сделай сайт про X» без деталей —
   можно самостоятельно принять разумные решения по стеку и содержанию
   (как это делает `developer`), но крупные решения (тон, структура,
   цветовая гамma) стоит кратко анонсировать пользователю.

## Структура репозитория

```
websites/
├── CLAUDE.md                 — этот файл
├── docs/
│   ├── workflow.md            — подробный пайплайн и конвенции
│   ├── brief-template.md      — шаблон брифа нового сайта
│   └── site-checklist.md      — чек-лист приёмки перед сдачей
├── .claude/agents/             — определения субагентов команды
│   ├── content-writer.md
│   ├── designer.md
│   ├── developer.md
│   └── seo-specialist.md
└── sites/
    └── <slug>/                — один сайт = одна папка
        ├── brief.md
        ├── content/
        ├── design/style-guide.md
        ├── seo/
        └── ... (итоговый сайт, структуру выбирает developer)
```

## Стек

Стек не фиксирован на уровне репозитория — под каждую тематику разработчик
выбирает подходящий вариант (обычный HTML/CSS/JS для простых сайтов,
статогенератор типа Astro/Next.js для сложных). Решение и его причина
фиксируются в `sites/<slug>/README.md`.
