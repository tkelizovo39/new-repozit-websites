# Пайплайн создания сайта

Подробное описание процесса, который ведёт главный агент (оркестратор) для
каждого нового сайта. Краткая версия — в корневом `CLAUDE.md`.

## Этапы

```
brief.md  →  content-writer  →  designer  →  developer  →  seo-specialist  →  приёмка
```

1. **Бриф.** Оркестратор заполняет `sites/<slug>/brief.md` по
   `docs/brief-template.md`, опираясь на запрос пользователя. Неясные
   пункты уточняет у пользователя до запуска команды, а не додумывает
   ключевые факты (аудиторию, цель, обязательные страницы).

2. **content-writer.** Получает путь к брифу. Отдаёт:
   - `sites/<slug>/content/sitemap.md` — список страниц;
   - `sites/<slug>/content/<page>.md` — текст каждой страницы.
   Оркестратор проверяет: все страницы из брифа покрыты, тон соответствует
   брифу, нет противоречий с указанными фактами.

3. **designer.** Получает бриф + content. Отдаёт:
   - `sites/<slug>/design/style-guide.md` — палитра, типографика,
     layout-принципы, компоненты, стиль изображений.
   Оркестратор проверяет: контраст текста/фона достаточен, стиль не
   противоречит тону из брифа.

4. **developer.** Получает бриф + content + style-guide. Отдаёт готовый
   сайт (стек выбирает сам — см. `.claude/agents/developer.md`) плюс
   `sites/<slug>/README.md` с описанием стека и инструкцией запуска.
   Оркестратор проверяет: все страницы из sitemap существуют и связаны
   рабочими ссылками, применены цвета/шрифты из style-guide, сайт
   адаптивен.

5. **seo-specialist.** Получает собранный сайт. Добавляет meta-теги,
   `sitemap.xml`, `robots.txt`, structured data, отдаёт
   `sites/<slug>/seo/seo-report.md`. Оркестратор проверяет: у каждой
   страницы уникальные title/description, sitemap.xml соответствует
   реальным страницам.

6. **Приёмка.** Оркестратор проходит `docs/site-checklist.md`, фиксирует
   статус в `sites/<slug>/README.md`, коммитит результат.

## Правила передачи между агентами

- Каждый агент получает **пути к файлам**, а не пересказ их содержимого —
  агент сам читает нужные файлы через Read/Glob.
- Если агент считает, что данных предыдущего этапа не хватает или они
  противоречивы — он должен сообщить об этом оркестратору, а не
  придумывать данные самостоятельно.
- Оркестратор не передаёт этап дальше по цепочке, пока не устранены
  замечания к текущему этапу.

## Параллелизация

`content-writer` и `designer` можно запускать параллельно (оба читают
только бриф и не зависят друг от друга), но `developer` должен ждать
завершения обоих, а `seo-specialist` — ждать `developer`.
