# «БрусДвор» — лендинг «Укладка брусчатки» (демо-проект)

Учебный проект по мотивам реального заказа с биржи фриланса. Реального
клиента нет — компания «БрусДвор», телефон, отзывы, цены и фото
«до/после» являются демонстрационными плейсхолдерами (см.
`brief.md` и пометки прямо в тексте страницы).

## Статус: готово (пройден чек-лист docs/site-checklist.md)

Все 4 этапа пайплайна пройдены и приняты оркестратором: `content-writer` →
`designer` → `developer` → `seo-specialist`. Перед реальной публикацией
нужно заменить плейсхолдеры — полный список в `seo/seo-report.md`
(домен, og-изображение, телефон, адрес, название компании при
необходимости).

## Стек и почему он выбран

Обычный **HTML/CSS/JS без сборки**, без фреймворков и без npm-зависимостей:

- Сайт — одностраничник (см. `content/sitemap.md`): 9 смысловых блоков на
  одной странице, без каталога, без похожих друг на друга страниц и без
  переиспользуемых шаблонов между разными URL. В такой ситуации
  статогенератор (Astro и т.п.) или SPA-фреймворк не сокращают
  дублирование — они только добавляют шаг сборки, который не нужен ни
  для разработки, ни для хостинга.
- Файлы открываются напрямую в браузере и без проблем размещаются на
  любом статическом хостинге (GitHub Pages, Netlify, обычный
  shared-hosting) без CI/CD.
- Все интерактивные элементы (мобильное меню, FAQ-аккордеон, обработка
  отправки формы, подсветка шапки при скролле) реализованы на
  vanilla JS — их слишком мало и они слишком просты, чтобы оправдывать
  React/Vue или сборщик.

## Структура файлов

```
sites/paving-landing/
├── index.html        — вся разметка страницы (9 блоков + nav + footer)
├── css/
│   └── styles.css    — переменные палитры/типографики, компоненты, адаптивность
├── js/
│   └── script.js     — мобильное меню, шапка при скролле, FAQ-аккордеон,
│                        демо-обработка формы заявки, год в футере
├── content/           — исходные тексты блоков (контент-райтер)
├── design/
│   └── style-guide.md — дизайн-гайд (дизайнер)
└── brief.md
```

Изображений в `assets/` нет: по брифу реальных фото нет, поэтому вместо
`<img>` с пустым/битым `src` использованы CSS/HTML-плейсхолдеры — блоки
с фоновым паттерном и подписью, прямо называющей сюжет будущего фото
(например «Фото-плейсхолдер: уложенная брусчатка во дворе частного
дома…»), в соотношениях сторон из `design/style-guide.md` (4:3 для
до/после и текстур, 3:2 для кадров процесса и т.д.), чтобы вёрстка не
«прыгала» при подстановке реальных изображений.

## Как открыть локально

Сборка не нужна — достаточно открыть файл в браузере:

1. Скачайте/клонируйте репозиторий.
2. Откройте `sites/paving-landing/index.html` двойным щелчком в
   Проводнике, либо перетащите файл в окно браузера.

Либо поднять локальный статический сервер (удобнее для проверки
относительных путей к шрифтам/скриптам и для мобильной эмуляции в
DevTools):

```bash
cd sites/paving-landing
python -m http.server 8000
# затем открыть http://localhost:8000
```

Для подключения шрифтов Google Fonts (Oswald, PT Sans) нужен доступ в
интернет — офлайн шрифты заменятся веб-safe фолбэками
(`Arial Narrow`/`Arial`), сайт останется читаемым.

## Что реализовано по дизайн-гайду

- Палитра — CSS-переменные в `css/styles.css` (`:root`), 1:1 с таблицей
  из `design/style-guide.md` (включая разделение «декоративного»
  `#C1622D` и «рабочего» `#A8501F» акцентов согласно проверке
  WCAG-контраста в гайде).
- Типографика — Oswald 600/700 для заголовков, PT Sans 400/700 для
  текста, подключены через Google Fonts с `preconnect`, с web-safe
  фолбэками из гайда.
- Layout — контейнер 1160px, брейкпоинты 767/1023, сетки карточек
  1 → 2 → 3 колонки, вертикальный ритм кратный 8px, отступы секций
  48/64/96px по брейкпоинтам.
- Компоненты — кнопки (primary/outline/ghost на тёмном), карточки
  услуг, степпер из 5 шагов (горизонтальный на десктопе, вертикальный
  на мобильном), карточки портфолио с парными фото «до/после» и
  бейджами ДО/ПОСЛЕ, карточки отзывов с обязательным бейджем «пример
  отзыва» и декоративной кавычкой, карточки цен, FAQ-аккордеон, форма
  заявки на светлой карточке внутри тёмной секции, sticky-навигация с
  прозрачным/непрозрачным состоянием, тёмный футер.
- Все обязательные пометки «демо»/«пример» из брифа и контента сохранены
  дословно: отзывы, цены, портфолио, контакты, телефон, футер.

## Компромиссы относительно style-guide.md

- **Карточки услуг**: в разделе «Компоненты» гайда карточка услуги
  описана как «иконка + заголовок + описание» (без фото), а в разделе
  «Стиль изображений» текстуры/фото прямо указаны как используемые «в
  карточках услуг», и в `content/uslugi.md` для каждой услуги описан
  свой фото-плейсхолдер. Чтобы не потерять ни то, ни другое, каждая
  карточка получила фото-плейсхолдер (4:3) сверху **и** линейную
  иконку-пиктограмму под ним — это объединение двух частей гайда,
  которые сами по себе не были явно состыкованы.
- **Карточки отзывов**: в оригинальных заголовках отзывов из
  `content/otzyvy.md` пометка «(пример отзыва)» была частью текста
  заголовка. В вёрстке эта пометка вынесена в обязательный
  бейдж-компонент «пример отзыва» над карточкой (который гайд отдельно
  требует как «не декоративный, а функциональный элемент»), а не
  продублирована ещё раз внутри заголовка — чтобы не получилось двух
  разных мест с одной и той же оговоркой на одной карточке. Смысл и сам
  факт пометки не потерян, только его расположение.
- **Выделение «популярного» тарифа** в блоке цен — гайд разрешает (но
  не требует) выделить один тип брусчатки как «популярный выбор». Такой
  информации не было ни в брифе, ни в `content/cena.md`, поэтому
  выделение сознательно не добавлено, чтобы не придумывать факт от себя
  — все три карточки цен оформлены равноценно.
- Реальных фотографий, логотипа и иконки favicon нет по брифу — везде
  используются описанные выше текстовые/CSS-плейсхолдеры вместо
  `<img>`.
- `<head>` намеренно оставлен минимальным (charset, viewport, временный
  `<title>`, подключение шрифтов) — meta-description, Open Graph,
  canonical, robots/sitemap.xml и структурированные данные не
  добавлялись: это зона ответственности следующего этапа
  (seo-specialist).
